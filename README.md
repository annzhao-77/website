## Repository layout

- `blog/posts/postN/`: original blog text (`.qmd`), R scripts, assignment README, and data or data-access instructions.
- `blog/posts/post2/results/`: generated job counts and skill-frequency tables.
- `blog/posts/postN/figures/`: figures generated by the R scripts; additional illustration files may also be present.
- `docs/`: rendered website output. Edit source files outside this folder, then render again.
- `_quarto.yml`: website configuration.
- `studentname-website.Rproj`: open this file in RStudio to work from the repository root.

## Quick start: reproduce Blog 2 from the included data

Install R, RStudio (optional), and Quarto. Open the `.Rproj` file above. Run these commands in the R Console from the repository root:

```r
install.packages(c("dplyr", "stringr", "ggplot2")) # once
source("blog/posts/post2/analyze_acme.R", chdir = TRUE)
```

This uses the included historical CSV and regenerates three figures and three summary tables. **You do not need to scrape the live website to reproduce the submitted analysis.** See the [Blog 2 README](blog/posts/post2/README.md) for file names, definitions, and optional scraping instructions.

## Other analyses

Run each script from its own post folder, or use `source(..., chdir = TRUE)` from the repository root:

```r
# Blog 3: first obtain your IPUMS extract; replace this example path.
Sys.setenv(CPS_DATA_FILE = "C:/path/to/your/cps_00001.csv")
source("blog/posts/post3/analysis.R", chdir = TRUE)

# Blog 4: install WDI, dplyr and ggplot2 first.
source("blog/posts/post4/worldbank_analysis.R", chdir = TRUE)
```

Blog 3 intentionally requires a locally obtained IPUMS file; its original microdata are not distributed here. Blog 4 uses its saved snapshot by default and downloads from the API only if the file is absent or a refresh is requested. Each post README describes its specific inputs and packages.

## Render the website

After regenerating any figures, run this in a terminal from the repository root:

```sh
quarto render
```

Or render a single post, for example:

```sh
quarto render blog/posts/post2/index.qmd
```

The website output is saved in `docs/`. Rendering a QMD that references saved PNGs does not rerun its separate R analysis script. To update the analysis, run the R script first, then render. Posts marked `draft: true` should be completed before publication.
